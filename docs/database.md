# Проектирование базы данных МаркетСклад

Статус: проект схемы. Таблицы будут создаваться постепенно через миграции.

## Общие соглашения

- У каждой таблицы есть id, created_at и updated_at.
- Связи обеспечиваются внешними ключами и индексами.
- Обязательные поля проверяются приложением и ограничениями базы.
- Денежные значения хранятся как decimal с двумя знаками после запятой.
- Количества товаров хранятся как целые числа.
- Служебные таблицы Rails не входят в 12 таблиц предметной области.

## 1. Пользователи — users

Поля:
- name — имя.
- email_address — уникальная электронная почта.
- password_digest — хеш пароля.
- role — роль: customer или employee.

Связи: пользователь имеет много заказов и отзывов.
Сотрудник может принимать поставки.

Самостоятельная регистрация создаёт только покупателя.
Роль сотрудника назначается отдельно, вне публичной формы.

## 2. Категории — categories

Поля:
- name — уникальное название.
- description — описание.

Связи: категория имеет много товаров.

## 3. Бренды — brands

Поля:
- name — уникальное название.

Связи: бренд имеет много товаров.

## 4. Товары — products

Поля:
- category_id — категория.
- brand_id — бренд.
- name — название.
- sku — уникальный артикул.
- description — описание.
- price — текущая цена, decimal(12,2).
- active — доступен ли товар для новых покупок.

Связи: товар относится к категории и бренду.
Имеет остатки, позиции поставок, позиции заказов и отзывы.

Цена должна быть больше нуля.
Товары с историей операций архивируются через active, а не удаляются.

## 5. Склады — warehouses

Поля:
- name — уникальное название.
- address — адрес.

Связи: склад имеет остатки, поставки и заказы.

В первой версии каждый заказ полностью обслуживается одним складом.

## 6. Остатки — stocks

Поля:
- warehouse_id — склад.
- product_id — товар.
- quantity — физическое количество.
- reserved_quantity — количество в резерве.

Пара warehouse_id и product_id уникальна.
Количество и резерв неотрицательны.
Резерв не может превышать физическое количество.

Доступно для покупки = quantity - reserved_quantity.

## 7. Поставщики — suppliers

Поля:
- name — название.
- email — контактная почта.
- phone — телефон.

Связи: поставщик имеет много поставок.

## 8. Поставки — supplies

Поля:
- supplier_id — поставщик.
- warehouse_id — склад назначения.
- received_by_id — сотрудник, принявший поставку; до приёмки пусто.
- status — draft или received.
- received_at — время приёмки; до приёмки пусто.
- notes — примечание.

Связи: поставка содержит много позиций.
received_by_id ссылается на users.

## 9. Позиции поставок — supply_items

Поля:
- supply_id — поставка.
- product_id — товар.
- quantity — количество, больше нуля.
- purchase_price — закупочная цена, decimal(12,2), неотрицательная.

Пара supply_id и product_id уникальна.

## 10. Заказы — orders

Поля:
- user_id — покупатель.
- warehouse_id — склад выполнения заказа.
- status — new, processing, shipped, completed или cancelled.
- recipient_name — имя получателя на момент заказа.
- delivery_address — адрес доставки на момент заказа.
- phone — контактный телефон на момент заказа.
- notes — пожелания покупателя.

Связи: заказ принадлежит покупателю и складу, содержит много позиций.

Данные получателя сохраняются в заказе и не меняются при изменении профиля.

## 11. Позиции заказов — order_items

Поля:
- order_id — заказ.
- product_id — товар.
- product_name — название товара на момент покупки.
- sku — артикул на момент покупки.
- quantity — количество, больше нуля.
- unit_price — цена на момент покупки, decimal(12,2), больше нуля.

Пара order_id и product_id уникальна.
Изменение текущей цены товара не меняет оформленный заказ.

Стоимость позиции = quantity * unit_price.
Итог заказа вычисляется как сумма стоимостей его позиций.

## 12. Отзывы — reviews

Поля:
- user_id — автор.
- product_id — товар.
- rating — целая оценка от 1 до 5.
- body — текст отзыва.

Пара user_id и product_id уникальна.
Один покупатель может оставить один отзыв на товар.
Отзыв разрешён после получения товара в завершённом заказе.

## Правила работы

### Поставки

- Новая поставка создаётся в статусе draft.
- Приёмка увеличивает физические остатки на складе.
- Пустую поставку принять нельзя.
- Приёмка выполняется одной транзакцией.
- Повторная приёмка не изменяет остатки.
- Принятую поставку и её позиции нельзя редактировать или удалять.

### Заказы и остатки

- Корзина первой версии хранится в сессии без отдельной таблицы.
- Цены и наличие проверяются сервером при оформлении.
- Нельзя оформить пустой заказ или заказать неактивный товар.
- Выбранный склад должен иметь весь заказ в доступном количестве.
- При оформлении резервируется товар, физический остаток не меняется.
- Проверка наличия, создание заказа и резерв выполняются атомарно.
- Параллельные заказы не должны приводить к превышению остатков.
- При отправке уменьшаются физический остаток и резерв.
- При отмене до отправки освобождается только резерв.
- Повтор операции не должен повторно менять остатки.
- После оформления состав и цены заказа не редактируются.

Допустимые переходы статусов:
- new → processing или cancelled.
- processing → shipped или cancelled.
- shipped → completed.

Завершённый или отменённый заказ дальше не меняет статус.
Возвраты после отправки находятся вне первой версии.

### Доступ и интерфейс

- Каталог доступен всем.
- Оформление заказа доступно авторизованному покупателю.
- Покупатель видит только свои заказы.
- Управление складом и каталогом доступно сотруднику.
- В формах связей показываются названия, а не числовые коды.
- Внешние ключи запрещают удаление связанных исторических данных.

## План REST API

Версия API: /api/v1.

Каталог:
- GET /products — список с поиском и фильтрами.
- GET /products/:id — карточка товара.
- GET /categories — категории.
- GET /brands — бренды.

Заказы:
- GET /orders — доступные пользователю заказы.
- GET /orders/:id — заказ с позициями.
- POST /orders — оформление заказа.
- PATCH /orders/:id — разрешённое изменение статуса.

Изменение каталога сотрудником:
- POST /products — создание товара.
- PATCH /products/:id — изменение товара.
- DELETE /products/:id — архивирование товара.

API возвращает JSON и проверяет права на сервере.
Механизм авторизации будет определён при реализации входа.
